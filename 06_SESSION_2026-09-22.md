## 1. What was built, by theme

The work falls into five threads. Every commit is a wired capability with a
non-hollow test or a piece of infrastructure; none is planning.

### The fact book — a real learning store (12 commits)

The scattered research/questions/notes were unified into one indexed fact book
(`facts.rs`) that Atlas actually reasons over:

- **Structured facts** — subject / attribute / value triples, not free text, so
  "my car is a Toyota" is a fact Atlas can answer against.
- **Entity resolution** — one thing under several names (aliases), so "the
  Corolla", "my car" and "the Toyota" reach one record.
- **Provenance** — an answer carries where it came from, so a *noticed* guess is
  hedged, never stated as fact.
- **Corrections in plain words** — "actually my car is a Toyota" supersedes the
  earlier value; the correction wins because it is timed by the same clock the
  capture is.
- **Bulk import** — a whole folder or document ingested at once, superseding on
  correction.
- **Spaced retention, bounded memory** — writes stay cheap as the book grows
  (sharded persistence), and nothing you *stated* is ever evicted.
- **Associative recall** — topic tags, and ageing a recalled fact against the
  note it rests on so a stale one offers to go re-read its source.

Still open here: semantic/embedding recall and contextual recall (learning #4
and #6). Both are gated on the local embedding model and plumbing that is not in
this tree yet — named, not silently dropped.

### Self-finishing, commissioning, shakedown (the 22 Sep sequence)

The directive was: complete self-finishing, move to commissioning, then
shakedown, then a refactor, crew running throughout.

- **Self-finishing** — Atlas reports its own remaining work split by who can
  finish it (Atlas / a run / you); the hard drafts use a stronger model and
  everything else stays local; and an unattended `land` is now **all-or-nothing**
  — it backs up every file it will overwrite and rolls back on any error, so a
  self-fix can never leave itself half-applied.
- **Commissioning** — `capability::commissioning()` classifies the 44 never-run
  capabilities: 42 verify automatically, **2** (the camera ones) need your eyes.
- **Shakedown** (`shakedown.rs`) — "run a shakedown" walks the never-run
  capabilities and verifies what it can without you: read-only checks now,
  visible ones on a one-tap go-ahead, data ones on first real use, and names the
  two that need your eyes. `check yourself` (`checkup.rs`) proves the install
  works on this machine in seconds.

The point of these three, in one line: **you do not have to sit and run
thousands of tests to trust a fresh install.** The thousands are a build-machine
gate. A person runs the seconds-long self-check and a short shakedown pass, and
the only thing that genuinely needs their eyes is the two camera checks.

## 2. Tree hygiene done for the merge

**Runtime `data/` is no longer tracked.** The baseline had 56 files under
`data/` committed — notes, live state, the vault, logs, the single-instance
lock, the self-work build sandboxes, and the per-install recovery key. All of it
is generated at runtime (the app recreates `data/` on first run; every test
builds its own data dir in temp), so none of it is source. Committed, it churned
the working tree on every run and shipped a secret key and real peer names in a
tree meant to go to friends. `data/` is now gitignored and untracked; the files
stay on disk so the running instance is untouched. **This is why the working
tree now stays clean across runs — which is what the merge needs.**

If your main-chat tree has the same `data/` files tracked, apply the same change
there before or during the merge, or they will show up as conflicts.

## 3. The test-binary consolidation — read this before adding a test

The suite compiled **each** `tests/*.rs` as its own binary, so a one-line source
change relinked the whole crate (tract-onnx, eframe, all) ~354 times before a
single test could run. That relink fleet was the slow part of a dev cycle.

Now `Cargo.toml` sets `autotests = false` and declares the targets by hand:

- `tests/all.rs` `#[path]`-includes **328** self-contained files → one binary,
  one link.
- **26** files keep their own `[[test]]` target, for reasons written into the
  TOML: **8** declare their own `mod common;` (a file submodule can't resolve
  through a `#[path]` include), and **18** drive the *global* vault/handover
  state that `roots::install_state()` shares per process behind a `OnceLock` —
  run together in one process they defeat each other's `ATLAS_HOME` isolation and
  leave each other handed-over. A process per file keeps that state to itself,
  exactly the isolation the old layout gave every file for free.

The test files did **not** move; the content guards that scan `tests/` read them
in place, unchanged.

**THE RULE (because `autotests` is off): a new `tests/*.rs` silently will not run
until it is registered.**

- Self-contained, no global vault/handover state → add
  `#[path = "NAME.rs"] mod NAME;` to `tests/all.rs`.
- Declares `mod common;`, or drives global vault/handover/`ATLAS_HOME` state →
  add a `[[test]] name / path` entry in `Cargo.toml` (its own process).
- Integrity: every `tests/*.rs` must be in `all.rs` xor a `[[test]]` entry —
  never both, never neither.

**`verify.sh` was updated to match.** It ran guards by name as standalone
targets (`cargo test --test wiring`); most guards are now modules inside `all`,
so a `run_one` helper resolves each name to its own target or a filter of `all`,
and the fallback loop and the file-count display now count test *targets* rather
than the 354 files. Run `./verify.sh --quick` (guards + lib, ~2 min) or
`./verify.sh` (full) as before.

## 4. One gap the merge gate caught, and how

Worth recording as a pattern. The crew wired `Intent::Refile` but never placed
it on either handed-over list, so a guest holding the laptop could re-file the
owner's notes — allowed by omission. The `handed_over` guard is built to catch
exactly this (every action must be refused or deliberately allowed, never
neither). It was **masked at commit time** because `handed_over` is one of the
process-isolated separate binaries and was not re-run in the focused
verification after the wiring landed — the full suite is what surfaced it.
`refile` now sits on `THE_OWNERS_OWN`, beside `capture` and `got_it_wrong`.

The lesson is the standing one for this tree: the full suite, not a focused
subset, is the merge gate — and a change that touches intent classification must
re-run the isolated guard binaries, not just the ones inside `all`.
